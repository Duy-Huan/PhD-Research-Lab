# v6.0.0-preview.1 — supervised Research OS

Audit: [readiness](audits/v6.0_readiness.md). This is an opt-in experimental release: the live scientific pilot and provider/Docker qualification required for stable v6.0 are not claimed.

`research_os.enabled=false` by default. Enable through Mission Monitor (`/monitor`, direct API with no inference). Existing v5.6 missions without `control` retain legacy behavior. New strict `MissionControl` briefs include exclusions, criteria, hypothesis lineage, engine allowlist, exact app backend/model, explicit API/opaque native billing permission, schedule/end date, priority, wall-time budget and compulsory review. Approval binds all of it. Changing intent requires a new draft with `control.predecessor_id`; pause the old mission first. No automatic scientific replanning or new billing permission is inferred from provider output.

Lifecycle: draft → awaiting_approval → scheduled/queued → running → awaiting_review → completed. Pause/cancel/failure/interruption remain explicit. Resume is a fresh exact-plan approval. Completed tasks never rerun. Pausing stops admission and signals native/CPU cancellation; uncertain external effects require reconciliation before retry. Recovery never repeats an interrupted paid admission. Scheduled time is earliest admission time, not a machine wake-up service; the app must remain running. Native session/private transcript observability remains partial; workspace reconciliation records exposed files only.

Immutable charter versions define Topic goal hierarchy/dependencies, priorities, permissions and aggregate reasoning/active-time budget. Directed retrieval edges permit only the named source Topic in status reports; hierarchy does not grant retrieval or task write access. New charters have separate approved budgets rather than silently expanding old ones. Mission tasks remain bound to one Topic. Project reports include registered claims/status, experiments, BibTeX, workspace gaps, admissions and audit. They do not write a paper or approve claims. Artifact download rechecks ownership and hash.

New app reasoning bypasses legacy auto/cloud fallback: it calls the approved fixed local or API transport. API use requires `allow_api_billing=true`. Native OpenScience/Feynman billing is opaque to this control plane, so it also requires that explicit permission until subscription-only runtime qualification exists. No credentials are extracted. Quota/rate-limit failures store a 15-minute provider cooldown per project, pause subsequent admission and consume the failed attempt/call; no automatic retry or undocumented quota estimate. Separate projects have separate circuit records; central hardware slots remain process-wide. Reported tokens/currency remain null when unavailable.

API under `/api/research`: GET/PUT `/os-settings`; GET/POST `/charters`; mission endpoints add POST `.../request-approval`, `.../pause` `{note}`, `.../review` `{note}`, GET `.../report`, GET `.../artifacts/{task}/{index}`. Existing approve/cancel/retry APIs apply. JSON schema remains available through OpenAPI. The local researcher API is trusted-user authority, not multiuser authentication.

Schema 4→5 adds charters, usage and breakers, keeping `research.v4.sqlite3.bak`. Stop the app, archive the whole research folder and restore the matching backup with prior code to roll back. User data/engine config is never reset. Existing skill/plugin registries and custom experiment routes are preserved; no duplicate marketplace or orchestrator.

Acceptance: baseline prerequisite 52 tests OK (1 privilege skip); Research OS + mission/protocol/governance/launcher suites: 44 tests OK. Harness `python -B tools/research_harness.py --stage 6.0 --probe-engines` passed literature inspection, two independent native workspace file reconciliations, two actual CPU runs with independent reproduction, unresolved citation rejection and forced-outage no-repeat recovery. Sources/workspace content are labelled fixtures; human approvals are simulated by harness. Full trace/probes: `artifacts/v60/harness.json`. No live inference was submitted. This is not a real scientific pilot or evidence of multi-agent superiority. Final UI checks and later-version compatibility results are in the final validation report.

UI regression: 97/97 passed, including direct Mission Monitor feature toggle and final review with the composer preserved and no inference. `artifacts/v60/measurements.zip` preserves raw measurements/logs and original audit records; portable report paths are redacted only in the summary JSON.

Limits: one task dispatch at a time, bounded trusted CPU fixture, no arbitrary code/GPU execution in this new control plane, no automatic publication. Existing Docker hardening remains independently gated; the harness does not claim a live container escape test. Next increment supplies missing v6.1 team compatibility via assignments on these same tasks.
