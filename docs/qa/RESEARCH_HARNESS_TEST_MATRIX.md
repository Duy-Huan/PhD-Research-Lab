# Research harness qualification matrix

This matrix describes the application research qualification responsibility. Development verification orchestrates it; it must not absorb the research runtime architecture.

| Layer | Required proof | Unavailable / incomplete outcome |
|---|---|---|
| Provider | Requested/returned model where available, real responses, repeated queries, timeout/auth/quota/error handling | BLOCKED/FAIL; model listing is not inference |
| 2D | User-visible actions, API/state changes, console/network errors, trace/screenshots, locale/responsive/error/recovery | NOT_RUN/BLOCKED for omitted mandatory journeys |
| 3D | Actual WebGL rendering and controls, state persistence and 2D return | Fallback rendering is not actual 3D proof |
| CLI | Real child process, persisted settings/menu/EN-VI parity, cancel/error and native provider containment | Scripted stdin does not certify manual terminal rendering |
| Context/memory | Selected sources/provenance, truncation manifests, privacy/cross-project isolation, native-vs-wrapped comparisons | No universal intelligence parity from a few prompts |
| Experiment | Actual executed code, raw data/seed/environment, failed and successful attempts | No invented metrics or copied expected values |
| Replay | Fresh execution or independent recomputation with checksums | Checksum integrity alone is not a replay |
| Paper | Real data-backed figure, provenance, compiled PDF and required scientific review | Synthetic QA fixture is not novel research; pending review blocks certification |

The 6.4.4 checkpoint's Golden Thread evidence and known provider/coverage gaps are preserved in the original task reports. They do not certify modified 6.5.0/6.4.5 sources. Full current-source qualification remains required.
