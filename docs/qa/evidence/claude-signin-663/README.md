# Claude Code sign-in in PhD Lab's container: evidence

Contract: `docs/qa/contracts/FQC-CLAUDE-SIGNIN-663.json`. All checks ran on the disposable server (`D:/qa663`, port 8791) with the owner's Claude subscription.

## Root cause

- PhD Lab runs Claude Code in its own container, whose home folder is separate from `C:\Users\<you>\.claude`.
- For Codex, `prepare()` already copied the host's `auth.json` into the container. Nothing did the same for Claude.
- Readiness ran `claude auth status` on the host, so it said `CONNECTED` while the container was signed out.

Live turn before the fix: `Not logged in · Please run /login` (session `as-ed3757fbc5`).

## Fix

1. **Share this computer's current access token.** `prepare()` copies it into the container home, without the refresh token, so the container can never rotate and sign out the host's sign-in. A `/login` done inside the container is kept. Readiness is `CONNECTED` only when the container can actually sign in.
2. **Long-lived token** (the durable fix requested by the owner).
   - The researcher runs `claude setup-token` once and pastes the token in **Settings → AI connections → Claude**. The token lasts about a year.
   - It is stored as a masked secret (`gateway.claude_code_oauth_token`). The API returns only `••••` and `has_…`.
   - Turns run the container launcher as a separate process that has no project configuration. So the parent process passes the token in that process's environment (`ClaudeCodeConnector.env`). The launcher writes it to a private `--env-file`, which is removed after the run.
   - The token never appears on a command line or in the plan file. Codex never receives it.

## Settings UI finding

- The Settings component that shows CLI status, official sign-in and now the Claude token (`GatewayConnections`) had been imported since 6.5.10 but never rendered. The owner had no screen for CLI connections, and unit tests passed only because they rendered the component directly.
- It is now rendered in **Settings → Models & AI Agents**, and `SettingsContracts.test.tsx` checks that through the real Settings screen.
- The shared `['models']` query cache could crash Settings when another component cached a malformed catalog. Settings, the connections panel and the CLI studio now accept only an array of providers.
- The ChatGPT-only hint ("no OpenAI API key") is now shown only on the Codex card.
