# Regression policy

`quick` and `targeted` reduce diagnosis cost; `feature` checks the affected integration and build before pushing. `pr` independently executes full offline regression and strict production coverage. `uat` performs selected real-browser exploration through the same harness. `full` adds actual research/provider/CLI/scientific qualification; `release` also requires protected human release authorization. No local scoped green result substitutes for a required GitHub gate.

Backend production line/branch and frontend line/branch/function/statement thresholds remain 100%. Do not reduce scope/exclusions, drop Python 3.11, weaken expectations, ignore test failures, reinterpret skips as success or substitute mocks to green CI. Unknown or dynamic dependency impact triggers a conservative broad suite. Full artifacts retain all failures; compact reports group repeated root exceptions without dropping case IDs.

Provider qualification needs actual inference and stable queries, not binary detection, authentication UI or model listing. Real scientific acceptance needs executed experiments, raw data, independent recomputation/replay, honest figures, compiled papers and required review. Synthetic QA fixtures must remain labeled synthetic.

Automatic repair is capped at three failed correction cycles per stable task/PR/defect grouping according to agent SOP, with persisted ledger and evidence. Stop the exhausted loop; do not reset a key, spin new run IDs or switch to paid services to hide failure. Unrelated useful work may continue while the blocker is reported.
