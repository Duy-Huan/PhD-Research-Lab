# Autonomous feature lifecycle

The executable SOP is [agent/DEVELOPMENT_WORKFLOW.md](../../agent/DEVELOPMENT_WORKFLOW.md). The owner authorizes normal feature development, scoped local verification, staged commits/pushes, PRs and eligible native dev auto-merge. This does not authorize paid external calls, bypasses, automatic qa/main merges or release approval impersonation.

The dev auto-merge policy requires an open non-draft same-repository feature/* PR by the trusted owner, a contract reference, current dev included, known clean mergeability, no blocking review, enforced admin protection, all configured checks successful on the exact head from the expected Actions app, and repository auto-merge enabled. It re-fetches the PR before requesting a normal native SQUASH merge with expectedHeadOid after eligibility is green. No --admin, direct protected-branch push or forged approval is permitted.

The policy has controlled Node tests for rejected main/qa/fork/draft/stale/missing/pending/skipped/wrong-app/wrong-SHA/bypass/review cases. Those tests verify policy logic, not a completed GitHub merge. The workflow_run handler loads trusted protected-main code; until that code reaches default main through the approved release flow, the new automatic handler is inactive. Native repository auto-merge may still be enabled manually for an eligible PR using the same safeguards.

Repair is bounded by the persistent ledger under agent/repair-ledgers. Initial TDD RED and planned diagnostic probes are not correction cycles. Failed automatic corrections count; a green diagnostic does not reset prior failures. After three, stop that loop and provide exact failing evidence. Preserve branches until GitHub confirms the merge SHA on dev.

The branch-protection read endpoint requires Administration:read, which the normal workflow GITHUB_TOKEN cannot request. The protected-main handler accepts an optional separate `AUTOMERGE_POLICY_READ_TOKEN` with only the repository permission needed to read policy; it never uses that credential for merging. No such secret was present in the real audit, and none has been copied from the developer machine. Missing/unreadable policy returns BLOCKED with no write. This is an additional activation prerequisite, not permission to weaken the protection check. See [official GitHub endpoint permissions](https://docs.github.com/en/rest/branches/branch-protection#get-branch-protection).
