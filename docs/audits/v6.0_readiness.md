# v6.0 readiness audit — 2026-10-22

Baseline: c30cb99, v5.6.0-preview.1; working tree clean. Specifications are feature requirements, not permission to spend money, enable GPU or publish research. No v6.1 team runtime exists. Extend the current worker and SQLite store; do not add another orchestrator.

| Component | Source evidence | Gap / implementation decision |
|---|---|---|
| Mission DAG/admission | agent/missions.py, mission_contracts.py | Existing persisted attempts and human approval. Add optional supervised lifecycle, charter, deadline, priority, review and pause without changing legacy runs |
| Scheduling/recovery | knowledge/research_jobs.py worker | One sequential project worker, interrupted admissions never auto-repeat. Reuse it; enforce new gates at dispatch, persist quota cooldown |
| Providers | capabilities.py, research_engines registry/contracts, providers/models.py | Native typed ports exist; configured app calls can silently fall back to cloud. New supervised dispatch must use an explicitly approved fixed backend without hidden fallback |
| Scientific provenance | corpus.py, execution/protocols.py, knowledge/verification.py, governance.py | Retain independent source/metric checks and human decisions; include their pointers in report bundles |
| Resources | execution/guard.py | Existing CPU/GPU/CLI/cloud slots; default one CPU and GPU. Keep finite native CPU protocol; arbitrary scientific shell/GPU remains disabled |
| UI and plugins | research.js, ui_actions.py, skills.py, plugins | Extend existing contextual drawer and direct APIs; retain composer and registries, no new marketplace |
| Team harness | none beyond mission task records | Add smallest v6.1 compatibility layer during v6.2, referencing existing tasks/attempts; logical roles are not fabricated running processes |

Threats: expired or mutated approvals, cross-topic disclosure, engine fallback causing API billing, provider quota loops, lost admissions on restart, shared artifact overwrites, fabricated verification, administrator access to local API. All new mutations remain local trusted-researcher operations; this app does not provide multiuser authenticated agent identities.

Selected architecture: opt-in configuration → immutable charter/mission briefs → the existing durable DAG worker → exact provider/resource admission → artifact hashes and ledger → human review. Cross-topic access is only explicit directed charter edges in project status/report retrieval; tasks keep their Topic ownership. v6.2 roles and v6.3 teams become subordinate task assignments, never top-level planners.

Plan: implement/test/commit v6.0, then audit and implement/test/commit v6.2, then v6.3. Acceptance uses isolated temporary app data, deterministic fault injection, real bounded CPU workers and explicitly labelled external transport fixtures. A live scientific pilot, native inference, GPU and Docker containment remain external qualification gates; release as experimental until those have evidence.
