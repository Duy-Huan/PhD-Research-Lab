# PhD Research Lab — v6.4.2 Baseline & Full-Stack Audit Report

## 1. Executive Summary
This audit verified every backend router (`backend/api/*.py`), storage schema (`backend/knowledge/research_store.py`), engine adapter (`backend/research_engines/*.py`), and React frontend module (`frontend/src/`) from v5.1 through v6.3, and reconciled all contract discrepancies before upgrading the platform to **v6.4.0**, **v6.4.1**, and **v6.4.2**.

## 2. Stage A Audit Findings & Remediations (v5.1 – v6.3 Parity)
| ID | Area | Finding | Resolution |
|---|---|---|---|
| A-01 | `TopicInput` (`/api/research/topics`) | React `TopicView.tsx` sent `{ name, description }` whereas backend `TopicInput` requires `{ title, description, keywords, sources }`. | Updated `Topic` contract in `types.ts`, `TopicView.tsx`, and `Header.tsx` to use `title` (with fallback to `name`), `keywords`, and `sources`, plus Topic Discovery, Scoped Papers, and Hash-Chained Ledger tabs. |
| A-02 | `MissionSpec` & `Task` (`/api/research/topics/{tid}/missions`) | React `MissionBuilder.tsx` and `TaskInspector.tsx` used `arguments` instead of `args` and omitted `preferred_engine: "deterministic"` for deterministic capabilities. | Updated `MissionBuilder.tsx` and `TaskInspector.tsx` to send `args: {}` and auto-assign `preferred_engine: "deterministic"` for deterministic capabilities. |
| A-03 | Mission Approval & Review Lifecycle | `MissionLiveWorkspace.tsx` lacked `request-approval` and `awaiting_review` (`/review`) transitions. | Wired `/request-approval`, `/approve`, `/pause`, `/retry`, and `/review` in `MissionLiveWorkspace.tsx`. |
| A-04 | Scientific Claims Governance (`/claims`) | `EvidenceReview.tsx` lacked mechanical verification (`/evaluate`) and researcher attestation (`/decision`). | Added source evidence linking, `/evaluate` trigger, and `/decision` (`accept` / `reject`) controls in `EvidenceReview.tsx`. |
| A-05 | Workspace Drawers (`outline`, `paper`, `code`, `protocols`) | `ContextualDrawer.tsx` had static placeholder text for `outline`, `paper`, and `code`, and no `protocols` drawer. | Implemented full interactive `OutlinePanel`, `PaperPanel`, `CodePanel`, and `ProtocolsPanel` in `frontend/src/features/workspace-tools/OutlinePaperCodePanels.tsx`. |
