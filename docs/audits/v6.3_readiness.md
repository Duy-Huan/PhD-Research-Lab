# v6.3 design gate — 2026-10-22

Baseline: 40e1173. v6.2 has strict roles, owner/verifier assignment, immutable role handoffs, scoped admissions, budget-preserving replan drafts and one serial worker. Acceptance: 52 backend tests OK, 98 frontend tests passed; three workflow families across single/fixed/adaptive templates (12 real local Mission executions including CPU reproduction). Observed wall-time differences do not establish productivity gains. Native versions remain OpenScience 2.0.152 and Feynman 0.5.51; private sessions/live scientific inference are unqualified.

Shared-state risks: task reports currently share a mission filename; canonical output replacement needs optimistic version checks; task envelopes have no cross-team receipt; running Mission between committed tasks is currently conservatively interrupted despite having no uncertain task. Resolve these without creating another orchestrator. Keep raw measurements and scoped native session references; no conversation dump memory.

Selected design: optional CollaborationPlan of up to four workstream charters, explicit task membership and dependencies, narrower tools/engines and partitioned budgets. Default automatic partition stays single-team unless multiple independent substantive branches justify domains. Same worker/resource governor dispatches logical teams serially. Separate Topic missions remain isolated; directed project-charter report access does not automatically authorize cross-topic messaging or file writes.

Add durable WorkOrder/EvidenceBundle snapshots and receiver receipts transactionally tied to existing tasks. Canonical output registry stores hash-checked references with compare-and-swap revision plus append-only history; it never lets team file writes target shared paths. Disputes and findings reuse v5.6 scientific claims/decision policy; human resolution never self-certifies a claim. Team metadata authority is the existing local trusted-researcher API, not fabricated external authentication.

Tests: useful partition/single fallback; malformed/forged handoffs; receipt idempotency and restart between publish/ack; output conflicts; Topic/project isolation; failed engine isolation; unsupported improvement challenge; permission escalation; resource denial; pause/review; same three fixed local workflow families compared against v6.2 single adaptive team. Stable release remains blocked on a real scientific pilot, live native-provider qualification and resource containment. Default multi_team_enabled=false.
