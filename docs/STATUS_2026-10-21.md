## Work completed in this continuation

- Added paper/web search with independent source error reporting. Sources include OpenAlex, Semantic Scholar, arXiv, IEEE Xplore and configurable DuckDuckGo/Tavily/Brave web search. IEEE metadata uses an API key when supplied and indexed web discovery otherwise. Google Scholar results use SerpAPI when configured; a direct Scholar search link remains available.
- Kept one-click saving from retrieved results. Open PDFs are downloaded when possible; metadata-only entries retain papers with unavailable PDFs. Duplicate detection and later PDF upgrades preserve existing bibliographic keys and inclusion choices.
- Added journal indicators with source/date provenance. Imported SCImago CSV data supplies SJR, best quartile, ranking year and categories. OpenAlex journal citation statistics remain separately labelled. Preprints/conferences and journals without matched ranking data are not assigned fabricated quartiles. The journal indicator is also exposed as a research MCP tool.
- Consolidated default-project PDFs under `data/references/` while retaining `data/library.json`. Legacy PDF migration copies before switching the pointer, preserves originals and fails on different same-name files. Explicit custom reference folders remain supported.
- Restored old curated concept/method knowledge to active context by importing `memory/knowledge.json` into project notes. Imports are idempotent, retain complete original fields and preserve the source file. Imported curated records are not discarded by the ordinary rolling note limit.
- Fixed context caching: empty directory creation and the current turn's event/manifest writes no longer invalidate otherwise identical context. Pin, outline, experiment-record, research-run and other-conversation summary changes invalidate it. Updates inside an existing run directory refresh measured metrics.
- Fixed provider/model connection behavior and Windows process cancellation fallback. Connection tests exercise the selected streaming transport; empty replies and unavailable configurations report errors. Provider health/authentication state can be refreshed after configuration changes.
- Strengthened the backend harness with immediate error logs, exact uncovered-line/branch checks and source snapshots. A run during source changes cannot certify the final working tree.

## Configuration and verification limits

Supported provider code does not supply account credentials. A provider still needs its endpoint/model and API key or its vendor CLI sign-in. Google Scholar requires a SerpAPI key, IEEE metadata search requires an IEEE key, and imported journal ranking data requires the correct ranking year. The application reports missing configuration and partial search failures.

Live ClearML server, Codex-account and LM Studio load/unload tests are opt-in. Windows symlink tests need Developer Mode/admin. Skipped tests are listed separately in the backend summary; mocked service tests do not establish live-account connectivity. Windows process-tree tests must run with permission to terminate the processes they created.

Run recovery resumes when the application is running. It is not a scheduler that runs while the computer/application is off. Scientific claims and venue metrics retain their stated verification level; human review and real experimental evidence are still required for publication decisions.

## Reproduce

```powershell
.venv\Scripts\python -B tools/backend_regression.py --out artifacts/backend-regression
node tests/frontend/run.js
```

The backend harness returns exit 1 for test failures, exit 2 for incomplete coverage and exit 3 when sources change during a passing run. All test data is isolated with `PHDLAB_DATA_DIR`; the real research project is not the regression fixture.
