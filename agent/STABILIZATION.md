# Source stabilization procedure

Read AGENT.md, STATE.md, PLAN.md and DEVELOPMENT_WORKFLOW.md first. Preserve all user changes and both original application/governance worktrees. Never delete skills/ or agent/ files.

1. Record branch, commit, dirty sources and canonical source identity. Inventory source components, implemented routes/workflows and existing tests before claiming coverage. Test-name matching is heuristic, never proof of absent behavior coverage.
2. Run existing suites with their assertions unchanged. Distinguish product failures from test setup, missing dependencies, host load, permission and infrastructure failures. Record PASS, FAIL, BLOCKED and NOT RUN separately, including skipped mandatory cases.
3. Maintain docs/qa/SOURCE_BASELINE_AUDIT.md, BUG_INVENTORY.md, FULL_VERIFICATION_REPORT.md, REGRESSION_COVERAGE_REPORT.md, RELEASE_READINESS.md and machine-readable defects.json. Every confirmed defect needs severity, reproduction, expected/actual, evidence, root-cause hypothesis, regression ID and repair status. An unconfirmed timing observation must not be invented into a fixed product defect.
4. Search GitHub for appropriate skills before new feature/repair implementation. Review contents, pin revision and retain license/provenance under skills/. Reuse Playwright, test-gap-audit and web-design-reviewer. Standards references inform the process; neither a skill nor axe scan certifies IEEE/ISO/WCAG compliance.
5. Create one fix branch per coherent bug group from latest dev. Explicitly record pending infrastructure dependencies rather than hiding them or merging an unqualified feature into dev. Write a behavioral reproduction, preserve RED, apply the smallest justified fix, then targeted/affected/feature checks and independent required CI. Maximum three repair cycles per stable defect group; never reset ledgers to evade the bound.
6. Browser tests target owned disposable application/data/profile. Test 2D first, then real WebGL3D and native CLI. Cover locales, responsive sizes, errors/loading/empty states, persistence, keyboard, pointer actionability and real network state. A visible DOM node can still be covered by an overlay. Preserve failure screenshots, traces, console/network events; visual baselines require review and must not be auto-accepted during a redesign.
7. Live AI testing uses the authorized exact available local model, bounded requests/time/tokens and explicit provenance. Keep existing exhausted TASK-UAT-LOCAL-ADAPTER blocked. Do not run paid providers or substitute a model to obtain PASS. Distinguish workflow completion from empirical/scientific validity and independently replay experiment outputs before qualifying papers.
8. Keep development verification separate from runtime research harnesses. Add every verified fix's meaningful regression permanently to the canonical selector/CI. Inspect changes for duplicated logic, API breaks, hidden exceptions and unbounded retries.
9. After stabilization/integration, freeze sources and run one comprehensive final release-candidate verification. Earlier baseline/targeted runs are diagnosis, not that final certification. Require current-source coverage, mandatory critical workflows, no unresolved release-blocking P0/P1 and every required CI check PASS. Report residual risks; never claim the entire system is bug-free.
10. User authorizes push and testing feature -> dev -> qa -> main once qualified. Use PRs and existing protections. Main still needs an actual eligible reviewer and production approval. Do not force merge or fabricate approval. A red Development gate means QA/main promotion is BLOCKED, not successful pipeline deployment.
