# Mandatory browser and AI-UAT procedure

Use the existing `scripts/verify.py`, existing Playwright configuration and development verification package. Do not create another framework or import development orchestration into application research runtime.

1. Read the feature contract, affected UI routes and actual implementation. Search GitHub for useful skills before feature implementation; use pinned reviewed local skills. Do not apply upstream personal-Chrome, paid-cloud, automatic account-signup or subjective scoring defaults to this repository.
2. Choose deterministic journeys first. Playwright is authoritative for browser regression and can run without an LLM. Use semantic selectors, disposable app/database and isolated browser contexts. Capture trace, screenshots, console/page errors, unhandled rejection and relevant failed API requests. Bound every operation.
3. LOW uses smoke without mandatory AI calls. MEDIUM uses affected E2E and optional exploration. HIGH/CRITICAL require necessary exploration/recovery evidence by contract. CRITICAL additionally requires independent acceptance review and explicit release approval. Missing required exploration is BLOCKED, never PASS.
4. Use `python scripts/verify.py --profile uat` for the Browser Use adapter. Its default model is the owner's LM Studio `spark-x2.5-4b`. Do not substitute another model or paid/cloud browser automatically. Browser Use dependencies are separate from application/runtime dependencies and are locked in requirements-uat.lock.
5. Each run owns a new app-data directory, database/profile, loopback port and browser profile. Never connect personal Chrome, copy personal cookies/storage, use personal accounts or expose CDP on a public interface. The adapter's browser proxy allows only its owned application origin; external HTTPS/HTTP destinations are denied. Python worker tools exclude filesystem, upload, arbitrary evaluation, search and subprocess actions. Runtime/file/network restrictions are defense in depth, not a claim of whole-machine OS sandbox certification.
6. The first-time adapter currently explores a narrow settings-language journey. Its scoped test server permits only language writes and denies provider/terminal/workflow launches. Other personas/capabilities must be separately implemented and qualified; do not claim all five personas passed. The default Spark path uses DOM, not visual model input. Saved screenshots permit separate visual review.
7. Save actions and expected versus actual results. AI observations remain UNCONFIRMED until a controlled reproduction. A subjective score, `ai_success`, screenshot existence or model response alone cannot qualify acceptance. The adapter checks actual VI -> EN config POST responses, persisted language and final visible Settings state for its declared narrow journey.
8. Reproduce potential defects; classify product/test/environment causes; add a deterministic behavior regression where feasible; then fix implementation and rerun the failing and affected suites. Controlled broken HTML/console/network fixtures are explicitly MOCKED harness self-tests; never count them as product defects or scientific results.
9. At most three failed automatic repair cycles per stable task/PR/defect group. Record them in agent/repair-ledgers/ledger.json; never reset the counter or choose another key to evade it. Inspect status with `python scripts/verify.py --repair-status --repair-key <recorded-key>`. For this active task `TASK-UAT-LOCAL-ADAPTER` has exhausted three cycles: do not invoke more exploratory model runs automatically. Continue independent CI/docs work and report the blocker. Future genuinely new feature work uses its own contract-linked stable key.
10. Codex, Claude Code and Antigravity must use the same commands and policy. Codex discovery, Claude/Gemini instruction bridges and shell execution are different capabilities; do not assume Antigravity discovers Codex skills. Document actual CLI/browser runs separately from configuration-only compatibility. Concurrent agents must use separate app servers/data and browser leases.

See `docs/qa/UAT_ACCEPTANCE_REPORT.md` for executed cases and blockers. No main/qa auto-merge. A required UAT gap blocks the corresponding GitHub acceptance gate even when a smoke suite passes.

## Configuration and evidence handoff

- `devtools/verification/uat_config.json` defines five personas, existing Playwright suites, affected path patterns and actual adapter support. `browser_selection` in the canonical report is a plan (NOT_RUN), never execution evidence. Only settings-language has an exploratory adapter today; other listed journeys remain NOT_IMPLEMENTED for AI exploration. Their deterministic suites can still run.
- Use `--uat-journey settings-language` explicitly for that adapter. Unsupported IDs block before a model call. The current task remains blocked by its exhausted repair ledger regardless. Never assign a new key to bypass it.
- CI loads changed and unchanged contracts whose `affected_modules` match the diff; required high-risk acceptance validates current-source evidence hashes, raw history, model/browser records, screenshot and trace. LOW/MEDIUM do not blindly need LLM runs. Critical review cannot be invented from a model completion.
- `defects.json` is the structured handoff: title, exact actions, expected/actual, classification, mode, source identity and proof references. An observation remains UNCONFIRMED until controlled reproduction. FIXED requires reproduction plus failing/passing behavioral regression with matching source and raw artifact digests; mocked fixtures never become production fixes. Read only compact findings before opening the relevant full logs.
- Run deterministic boundary checks with `python -m devtools.verification.unittest_worker output/playwright/<new-run>/boundaries.json browser_acceptance_integration --mode REAL_LOCAL`. These require built frontend, Node, Chromium and application dependencies, but no LLM. CI runs them in the browser job, separately from the Python-only backend matrix.
- Package a genuinely passing current-source UAT run using `python scripts/package_uat_evidence.py --report output/playwright/<run>/report.json`. The package deliberately retains review=PENDING. Do not package a BLOCKED run or edit metadata into PASS.

The owned application and Node/Chromium child processes receive an allowlisted environment: provider/GitHub credentials are not inherited. A canary regression verifies this before HTTP mutation assertions. Keep HOME/USERPROFILE unchanged when retained for platform path calculation; explicit app data/config/cache directories belong to the disposable lease. Do not publish the original private server-env-red attempt because its assertion diagnostic included the inherited environment; use the separately recorded safe RED/GREEN evidence.
